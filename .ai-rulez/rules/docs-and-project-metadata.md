# Docs and Project Metadata

Public-facing copy has drifted from reality repeatedly because these facts are hand-typed in many
places. Before editing any README, docs page, or package description, use the canonical values below.

## Canonical facts

- **Positioning**: codegen-first polyglot web toolkit. A Rust core plus **14 language bindings**,
  spec-driven codegen (OpenAPI, AsyncAPI, GraphQL, JSON-RPC, gRPC, SQL→HTTP), tower-http middleware,
  and an MCP server.
- **The 14 bindings**: Python, TypeScript/Node, Ruby, PHP, Elixir, Go, Java, C#, Kotlin, Dart, Swift,
  Zig, C FFI, WebAssembly. Rust is the **core**, not a binding — "a Rust core plus 14 language
  bindings" is the correct phrasing. Never write 15 (that miscounts Rust as a binding). **There is no
  R binding** — it was invented in `docs/llms.txt` and removed.
- **Maturity**: experimental and pre-1.0. APIs change between releases. Do **not** claim the project
  or its Rust core is "stable" or "production-ready" — that claim was removed deliberately. The
  honest framing also recruits contributors, which is the current goal (feedback, users, contributors).
- **Docs site**: `https://spikard.dev`. The subdomain `docs.spikard.dev` **does not resolve** — never
  link it. Never point a "Docs" link at the GitHub repo.
- **Licence**: MIT.

## Generated vs hand-written — check before editing

Editing a generated file wastes the edit; the next regen reverts it.

**Generated by alef (edit the source, never the output):**

- `packages/*/README.md` and `crates/spikard-*/README.md` ← `templates/readme/*.md` + the
  per-language `[crates.readme.languages.*]` blocks in `alef.toml`.
- `docs/reference/**` — wiped and rewritten by `alef all --clean`.
- Package manifests (`package.json`, `composer.json`, `pubspec.yaml`, `*.gemspec`) ←
  `alef sync-versions`.

**Hand-written (no generator will fix or protect these):**

- **`README.md` at the repo root.** `templates/readme/root.md` looks like its template but nothing
  renders it — `alef.toml` has no root-readme entry. The two files are edited **in tandem, by hand**.
  When you change one, change the other, or they silently diverge.
- `docs/**` except `docs/reference/**` — including `docs/index.md`, `docs/llms.txt`, `docs/mcp.md`,
  and everything under `docs/guides/` and `docs/getting-started/`.
- `zensical.toml` (including `site_description`), `CONTRIBUTING.md`, `Taskfile.yaml`.

`docs_url` and `description` in `alef.toml` are **source** — they propagate into every published
package README, so a wrong value there ships to 15 registries.

## Version pins in prose

`alef sync-versions` covers manifests, not prose. These files hard-code a version by hand and must be
updated with every minor release:

- `docs/getting-started/installation.md` (Maven, Gradle, pubspec, SwiftPM, Zig tarball, mix.exs)
- `docs/llms.txt` (installation snippets section)
- `README.md` and `templates/readme/root.md` (the Elixir `~> x.y` row)

Verify with `task docs:check` (`alef validate versions` — manifests only; prose still needs a human
eye). `task docs:gaps` reports snippet coverage and is deliberately **not** part of `task check`,
because it exits non-zero while the good-first-issue backlog is open.

Do not add a bespoke consistency script — alef already owns version and snippet validation.

## Contributor onramp

The goal is feedback, users, and contributors. Keep the door open:

- `good first issue` — scoped to be finishable in an evening. The current set is per-language
  documentation snippet gaps (`docs/snippets/<lang>/`), found with `alef snippets gaps`.
- `help wanted` — the roadmap subsystem epics, each backed by an ADR.
- README and `CONTRIBUTING.md` both link these labels. Keep those links working.
